# Module 02 Lab — Mini Sprint Planning Session

## Objectives

By the end of this lab your team will have:

- Broken a feature brief into a set of INVEST-compliant stories
- Estimated each story using relative story points
- Agreed a sprint goal and selected stories that fit the team's capacity

## Setup

- The [`feature-brief.md`](feature-brief.md) from this lab
- Your team from Sprint 1 (or a team assigned for this exercise)

## Task sheet

Run this as a real mini sprint planning session, not a written exercise, assign someone to
facilitate (acting Scrum Master) and someone to represent the Product Owner's intent from the
brief.

1. **Read the brief together** and ask any clarifying questions a real Product Owner might be
   able to answer (assumptions are fine where the brief is silent, just write them down).

2. **Break the feature into stories**
   Split "Spending Insights Dashboard" into 4-7 individual stories, each following the INVEST
   criteria from Module 01. Write each as a proper user story with acceptance criteria.

3. **Estimate each story**
   As a team, estimate every story using story points on the scale 1, 2, 3, 5, 8, 13. Use a
   Planning Poker style vote (everyone reveals a number at the same time) rather than
   discussing a number first and anchoring on it. Where votes disagree significantly, discuss
   *why* before re-voting, don't just average the numbers.

4. **Check against capacity**
   The feature brief gives you a team capacity of 30 person-days for the sprint. Using a rough
   rule of thumb (your team can decide, e.g. 1 point ≈ 1-2 person-days), work out how many of
   your stories realistically fit in this sprint. You may not be able to fit them all, that's
   expected and realistic.

5. **Agree a sprint goal**
   Write a single sentence sprint goal describing the value this sprint will deliver, not a
   list of the stories themselves. A good sprint goal survives even if one lower-priority story
   in the sprint has to be dropped.

## Acceptance criteria

- 4-7 stories, each with acceptance criteria, covering the feature brief
- Every story has an agreed story point estimate
- A clear statement of which stories fit within the 30 person-day capacity, and which don't
- A single-sentence sprint goal that describes value, not a task list

If you finish early, compare your sprint goal with another team's, did you both interpret "not
like a full accounting tool" the same way?

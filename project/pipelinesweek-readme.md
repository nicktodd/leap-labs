# Pipelines Week - Project Friday Guidance

## Context

**Note on this file:** the curriculum's order has changed since this was written. Agile/Scrum
fundamentals, ceremonies, and the PR workflow are now taught the week before (Foundations),
not this same week - the paragraph below still describes the original combined content. The
Paragraph and Friday session below may need a rewrite to reflect that this week is now CI/CD-
and security-focused only, with the Agile/backlog work already under the team's belt from last
week. Left as-is pending a decision on how to adjust.

This week's teaching covers a deeper dive on CI/CD, Docker multi-stage builds,
Infrastructure as Code (IaC) concepts, building a CI pipeline, OWASP Top 10, and Secure Code
Warrior (SRE is no longer part of the curriculum). Agile/Scrum fundamentals, ceremonies, the PR
workflow and peer review were covered previously, in Foundations.

There is no capstone code deliverable this week from this track - the platform's own data model
build happens this same week too, via the parallel Data week track (see
[`dataweek-readme.md`](dataweek-readme.md)). This Friday is about starting to run as a team the
way the rest of the programme expects: reading a real requirements spec, working with a
customer, and standing up a backlog.

This is guidance, not a rigid checklist. Teams can spend Friday however they judge best, but the
suggestions below are a sensible starting point given what's just been taught.

## Suggested Friday session

1. Plan for, and then hold, a customer meeting with your nominated customer instructor, in
   another room.
2. Based on the requirements document and what came out of the customer meeting, identify user
   stories from the requirements spec and capture them as a product backlog.
3. Agree as a team how you'll manage that backlog for the rest of the programme, tool, format,
   who owns refining the backlog, and when you'll revisit it.

## What to present to the class

- Reflections on how the customer meeting went, what was easy to get out of them, what wasn't.
- An initial overview of your current backlog.
- An overview of how you're planning to manage the backlog going forward.
